10 November 2026. Parser/retrieval identities advance to 0.18.0; document chunker remains 0.17.0. Existing approved evidence is not invalidated. Branch: `dev`; no commit/push performed by this increment.

## Implemented

- Typed combined Full/Shared XLSX ingestion, preserving original sheet and physical row. The existing real workbook is supported without converting away its original provenance. Generic workbooks retain the ordinary document path.

- Strict schema, positive technology, complete ordered milestones, damaged text checks, formula/error/hidden/merged worksheet rejection. No formula evaluation, source truncation, guessed categories or implicit cross-document deduplication.
- Local source-backed acceptance runner and focused unit/API/database regressions. Submission guide documents setup, architecture, demo and actual limits. Interface redesign is deferred as requested.

## Operating instructions / limits

Run the install and forward migrations before restart; see [schedule setup and API contract](SCHEDULE_SEARCH.md) and [submission guide](SUBMISSION_GUIDE.md). Schedule CLI now emits a result envelope. The old simple GET schedule endpoint remains available for compatibility. Advanced new options are API/CLI-accessible; no interface redesign was made.

“Open” means the imported final deadline has not passed on the stated reference date, **not confirmed capacity or booking availability**. Sources are imported snapshots, not synchronized website feeds. Independent files can overlap: retain their provenance or scope `document_id` to the chosen authority. Named-month/quarter prose and arbitrary natural language are not claimed supported; use explicit filters when clarification is requested.

This increment does not approve unverified manufacturing formulas/charts, substitute missing FAQ answers/URLs, repeat prior cloud evaluations, rotate shared secrets or declare enterprise identity/hosting complete. Those source/organizational decisions remain outside what local test results can establish.
