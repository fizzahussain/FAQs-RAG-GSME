# GSME Muse changes

## 0.19.12 — hosted retrieval outage recovery

- Diagnosed the fallback gap: Ollama previously replaced answer generation only, so Cohere query-tokenization/embedding or reranking failures stopped before the answer fallback could run.
- Added hosted-only optional local recovery using existing BM25 indexed points and bounded Ollama relevance scoring, followed directly by Ollama generation. This is explicitly degraded LLM reranking, not a Cohere-equivalent cross-encoder. No re-embedding, model download or external evaluation is needed.
- Retained SQL point prefilters, tenant/model boundaries, source rechecks, whole-unit assembly, citation validation and abstention. Local failure does not release unreranked answers. A configured Cohere threshold fails closed rather than being silently reused on local scores.
- Added bounded process-local provider cooldowns, key-separated recovery state, proper rerank quota/Retry-After classification, safe stage logs and a visible local-recovery indicator. Local parsing/indexing approval rules are unchanged; offline document ingestion is not claimed.
- Bounded local CPU work separately with a default ten-candidate cap (raised to requested top-k when necessary), 6,000-byte whole-passage input batches and a 120-second scoring deadline. Reduced coverage is explicit in UI/diagnostics. A 32-entry, 120-second cache stores only input hashes and validated scores; current authorization is still checked per request. Added local progress events, batch/cache timing logs, local-only model-name checks and distinct safe offline/busy/timeout/invalid-ranking messages for JSON and SSE responses.
- Added regressions for quota recovery, cooldown call suppression, local ranking failures/invalid outputs, revocation, lexical tenant/model filtering, candidate bounds, score-cache expiry and direct-to-local checked generation. Full regression run: 402 tests in 544.250 seconds, 399 passed, three skipped, no failures/errors. All three skips require the missing original three-page validation PDF. A final 51-test retrieval/API recheck covered the last candidate-limit/progress/error refinements and passed without skips. JavaScript syntax and whitespace checks passed.
- Real local qwen3:4b checks used synthetic public/private fixtures in isolated PostgreSQL/Qdrant, with a simulated Cohere quota failure and external generation forbidden: JSON and streaming endpoints returned cited answers, repeated search skipped Cohere, and private fixtures remained excluded. Observed first JSON request: 109.94 seconds; repeated streaming request: 18.20 seconds. A separate ten-candidate local ranking selected the expected top passage in 43.98 seconds; its repeat used the score-only cache without another inference. These are availability checks under local test load, not company-corpus quality certification or latency guarantees. No new company-content Cohere calls, document re-embedding or production data migrations were performed. This increment is intended for the `retrival` branch and fast-forward merge to `dev`.
